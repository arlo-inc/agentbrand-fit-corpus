# Atom Types & Front-Matter Convention

Every file in this corpus begins with a YAML front-matter block. This block is the contract between the repo and the L12 ingestion pipeline. When SUB-001 runs, it reads this block and treats each file as a pre-staged atom with full provenance.

No file is committed without it.

---

## The Block

```yaml
---
source_url: https://example.com/path/to/source
source_type: guide_article
captured_via: manual
captured_at: 2026-05-02
domain: crimson_desert
tags: [boss_fights, staglord, parry_timing]
title: "Optional human-readable title"
notes: "Optional capture notes — context, caveats, why this was saved"
---
```

---

## Field Definitions

### `source_url` (required)

The canonical URL where this content originated. If the content was generated by an external model, use the model's session URL if available, or `internal://model-name/yyyy-mm-dd-topic-slug`.

### `source_type` (required)

One of:

| Value | Use For |
|-------|---------|
| `guide_article` | Long-form written guides (PC Gamer, GamesRadar, etc.) |
| `video_transcript` | Transcribed YouTube or other video content |
| `video_notes` | Hand-written notes from watching a video |
| `patch_note` | Official patch / update notes |
| `reddit_thread` | A Reddit post + relevant comments |
| `forum_thread` | Other forum threads (Steam discussions, official forums) |
| `official_page` | Pearl Abyss official site, Steam page, press releases |
| `wiki_page` | Fandom or other wiki pages |
| `research_dump` | Raw output from an external model (OpenAI, Gemini, Grok, Arlo) |
| `screenshot_set` | A collection of in-game screenshots with descriptive notes |
| `map_reference` | Map images with location annotations |

### `captured_via` (required)

How the content was added to the corpus.

| Value | Meaning |
|-------|---------|
| `manual` | Hand-written or hand-copied by the governor |
| `scraper` | Pulled by Firecrawl or another automated tool |
| `openai` | Surfaced by an OpenAI model (ChatGPT, GPT-4, etc.) |
| `gemini` | Surfaced by Google Gemini |
| `grok` | Surfaced by xAI Grok |
| `arlo` | Surfaced by Arlo himself |
| `other_model` | Any other external model — note the name in `notes` |

### `captured_at` (required)

ISO date of capture: `YYYY-MM-DD`. Time-of-day is not required.

### `domain` (required)

The subject domain. v1: always `crimson_desert`. Future expansion will add additional domain values; the field exists now to make that expansion non-breaking.

### `tags` (required, can be empty list)

Free-form list of topic tags. Use snake_case. Examples:

- `boss_fights`, `staglord`, `myurdin`, `golden_star`
- `legendary_horses`, `mounts`, `dragon`, `mech`
- `hero_contribution`, `reputation`, `side_quests`
- `parry_timing`, `combat_basics`, `weapon_skills`
- `cooking`, `fishing`, `alchemy`, `gathering`
- `kilden_workshop`, `pailune`, `abyss`
- `gear_progression`, `bloodstone`, `azurite`
- `patch_1_0`, `patch_1_01`, `hotfix`

Tags help the Librarian cross-reference atoms during filing. Better to over-tag than under-tag.

### `title` (optional)

Human-readable title. Helpful when the URL slug is opaque.

### `notes` (optional)

Free-form capture notes. Use this for: why the atom was saved, caveats about source quality, conflicts noted with other atoms, model-specific context (e.g., "Gemini hallucinated boss name — corrected manually before commit").

## Examples

### Example 1: A PC Gamer guide article

```yaml
---
source_url: https://www.pcgamer.com/games/rpg/crimson-desert-staglord-guide/
source_type: guide_article
captured_via: scraper
captured_at: 2026-05-02
domain: crimson_desert
tags: [boss_fights, staglord, parry_timing, early_game]
title: "How to beat Staglord in Crimson Desert"
---

# How to beat Staglord in Crimson Desert

[content here]
```

### Example 2: A Gemini research dump

```yaml
---
source_url: internal://gemini/2026-05-02-hero-contribution-mechanics
source_type: research_dump
captured_via: gemini
captured_at: 2026-05-02
domain: crimson_desert
tags: [hero_contribution, reputation, side_quests, gear_progression]
title: "Hero Contribution mechanics — comprehensive breakdown"
notes: "Gemini deep research run. Cross-checked claims against official wiki; one discrepancy on contribution-cap noted inline. Treat capped value as suspect until confirmed."
---

# Hero Contribution mechanics

[content here]
```

### Example 3: A YouTube video transcript

```yaml
---
source_url: https://www.youtube.com/watch?v=EXAMPLE_ID
source_type: video_transcript
captured_via: manual
captured_at: 2026-05-02
domain: crimson_desert
tags: [legendary_horses, mounts, eastern_grasslands, location_guide]
title: "Every legendary horse spawn location | Channel Name"
notes: "Auto-captioned, lightly cleaned. Speaker errors at 4:32 and 11:08 left as-is."
---

# Transcript

[content here]
```

```yaml
---
source_url: https://www.reddit.com/r/CrimsonDesert/comments/EXAMPLE/

notes: "OP plus top 5 comments. Skipped low-effort replies."
---

[content here]
```

## Filing Discipline

Three rules the Librarian will enforce when L12 lands. Following them now means zero rework later.

1. **Provenance is non-negotiable.** An atom without `source_url` and `captured_via` cannot be cited. The Companion will refuse to surface it. Don't create unciteable atoms.

2. **One source per file.** A single markdown file represents a single atom. If you have two Reddit threads on the same topic, they are two files.

3. **Conflicts are flagged, not resolved.** If a Gemini dump says one thing and a PC Gamer guide says another, commit both with a `notes:` field on each pointing at the conflict. The Librarian retains both atoms; the Companion surfaces the conflict to the governor at retrieval time.

---

## Adding a New `source_type`

If a new content shape appears that doesn't fit the table above, add it here as a row, commit the schema update, and use it. The schema is meant to grow. Don't shoehorn content into the wrong type.
